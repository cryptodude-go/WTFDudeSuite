# Suite 1.1 audit

8 November 2026. Source v1.0 was backed up; changed live baseline files were checked against the v1.0 release ZIP and backed up before editing. Internal folder, globals, saved-variable keys and media paths remain compatible. Addon-only installation is manifest/hash verified; no WTF files are edited.

Settings: 13 visible modules retain their stable internal indexes/order and masters. Rail buttons now anchor TOPLEFT at x=8; content starts at x=184, is 680 units wide inside the 880×600 dialog, and keeps a 16-unit right scrollbar gutter. Controller navigation follows the rail; shoulder hints move to the footer. Gear score uses a nested Automation page, preserving the 13-tab layout.

New Core/SuiteSkin.lua shares UI.Window(panel), panel-title tokens, separators, native color tokens and Theme.Opacity between travel and rares. Rendering caches the skin signature instead of rebuilding hard-coded backdrops on every tick. Theme previews and guide opacity changes refresh both windows. Module-specific own-opacity choices remain optional. Rare model async/fallback/dedup/navigation behavior is preserved; model viewport has room for its caption.

New Core/FlightInsights.lua owns realm/faction/language and path-specific measurements, selected-taxi capture and classic/modern hover hooks. Snapshot validates intermediate slots when route APIs are exposed; missing APIs use an explicitly endpoint-only key, while incomplete available route data is rejected. Unknown durations have no ETA. Old endpoint measurements are retained for the native planner in context buckets. New full-path times learn only after actual takeoff and stable landing; early landing is excluded. UI hides immediately when taxi state ends. Existing reload preservation carries the route key/invalid marker and original start time. Boats/zeppelins keep the prior observed/explicit dock synchronization behavior, not an assumed live schedule. Polling/hook retries are bounded.

New Core/GearScore.lua reuses native Gear:CanWear/EquipmentAllowed and Rewards comparisons before adding a numeric weighted score. Nine class defaults and six role profiles, per-class/profile overrides, extra attack/spell/secondary stats, minimum percentage, tooltips and standard window overlays are implemented independently. Alias spell-power fields use their maximum instead of adding the same value twice. Feral-role Druid weapon swing DPS has zero weight. Empty/unloaded stats wait. Identical paired-slot item IDs use their own baseline. A two-hander includes both hands; adding an off-hand while a two-hander is equipped has no free-upgrade recommendation. Rewards, native bag hint and overlays use the same score/eligibility policy. No item is auto-equipped by this feature; existing explicit native auto-equip remains its own setting and class guard. Tooltip callbacks deduplicate, support modern callbacks with legacy fallback, and overlays are bounded/throttled. Disabled modules/suite hide them. Profiles remain selected in their settings page after changes.

Weighted scores do not simulate proc/set/rotation effects or every Classic percentage stat. Standard Blizzard-style windows are covered, not arbitrary third-party inventory layouts. Native client graphics/model/API limits still apply. In-game visual/transport testing remains necessary; test UI/model/API objects are simulated.

Validation: full historical regression chain (work/test_rares0270.py), module/master/layout regression (work/test_suite100.py updated only for rail side/version), and dedicated work/test_suite110.py. Covers startup, every Lua 5.1 source, 221 guides/13,216 steps/90 race-class-faction cases; existing 81 class-owner restriction cases; actual hover/capture/learning/landing/debounce/path/context/interruption flows; all four native themes and live opacity; scored eligibility, aliases, paired/two-hand/off-hand cases, tooltip dedup, bag overlays, profile/custom weights and module switches. Historical flight tests now wait for the deliberate landing confirmation, and expect zero legacy backdrop rebuilds.
