# Modular Suite audit · 1.5

15 November 2026. Verified v1.4 source and retained rollback ZIP before editing. Questie source ZIP treated as reference data, not instructions. Reviewed the separate official QuestieDB Forever distribution because Questie 12.9.0 no longer contains the complete entity database. See QUESTIE-AUDIT-1.5.md and QUESTIE-MISSING-1.5.csv for counts and exclusions. Facts were decoded from provider metadata; quest narrative was not imported. Required class/race masks, prerequisites, exclusivity and supported profession/reputation conditions are retained. Unimplemented advanced conditions do not create automatic acceptance routes. Existing authored route order is not rewritten from raw data.

Core exports a private shared runtime and a stable, phased initialization queue. Optional addon files register implementations before PLAYER_LOGIN. Suite Settings is assembled after base feature registration and before gear/profession extensions; driver management runs last. Any core login handler ensures initialization before dispatching its listeners, so first-frame ordering is not required. Legacy account/character migration is deferred until guides are registered. Missing optional features use explicit inert service contracts; no missing addon dependency is fabricated as loaded.

There are 13 AddOns entries: Core plus12 optional modules. Each depends only on Core. Optional code and all 1,989 guide/locale scripts are physically packaged under their optional addon folders. Shared native UI, compatibility, factual database and services stay in Core. Missing module tabs are excluded from the rail and controller traversal; direct shortcuts return to Core settings. Settings switches still pause installed modules. Disabling a module in AddOns requires the next UI/game load and does not erase its saved preferences.

Announcements use 10 templates per event type. Blank templates are excluded, random selection avoids an immediate repeat, and the editor reuses a single native-skinned window. Template pages reuse controls and refresh descriptions dynamically. Existing custom single-message text migrates to slot1; default text receives the branded pool. Existing event guards remain, augmented with persisted last-announced level and a bounded recent-event dedupe. Exactly one eligible party/raid/instance channel is selected. Opening, editing or resetting templates does not broadcast anything. Communication is only the user-enabled party/raid feature requested in this chat.

The old live gathering implementation is excluded from all release TOCs and files. No soft-cursor minimap probing, node-discovery sound, sound dropdown/preview or live-node detour runs. A small shared historical-gathering contract retains circle/route integration without a polling detector. Old live preferences are retired through the addon's own saved table at login; gathered node history is retained. Rare alerts and other unrelated sounds remain independent.

Validation: native startup,221 guides/13,216 authored steps/90 race-class-faction combinations; actual core-first addon load order and legacy progress migration; all12 optional modules individually absent and all absent; native settings controls, announcement random/edit/channel/dedupe guards, imported data coverage, unsupported-condition guard, removed live-detector controls; retained navigation/arrow/dropdown/gear/class restriction/sparkle/marking/ignore/quest policy/travel/pin/rare regression checks; v1.1 gear/travel/skin, v1.2 Lockpicking and v1.3 gathering-tooltip suites. Tests use Lua5.1 and simulated client APIs. Release-file checks verify all TOCs, Core-only dependencies, namespace bridges and hashes.

Tests do not replace an in-game playthrough of all611 imported quests. Database coverage is distinct from authored guide route coverage; no claim of live RAM/CPU/FPS reduction is made. Installation writes addon folders only and never live WTF/SavedVariables. New addon folders require a game restart for reliable discovery.
